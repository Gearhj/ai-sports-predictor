## Operational Defects

1. **No resumable boundary after file generation.** Completed Parquet work was not bound to a durable recovery checkpoint before identity loading.
2. **One long transaction.** Database work remained all-or-nothing across an hours-long workflow, making rollback safe but forcing expensive replay.
3. **Chunked ORM identity persistence at bulk scale.** Approximately 737,259 mappings were headed through roughly 1,475 query/flush cycles rather than PostgreSQL-native bulk loading and set-based reconciliation.
4. **No heartbeat.** Stdout and stderr remained empty during the execute attempt, so operators could not distinguish progress, degraded throughput, lock wait, or a hang.
5. **No stage-level runtime limits.** The command had no enforced checkpoint-and-stop behavior at the required overall bound.
6. **Repeated source work.** Unchanged archives, the 9.27 GB plays source, and completed materializations were rescanned or regenerated across attempts.
7. **No durable hash cache for restart.** Verified unchanged files and source inputs were not reused through a versioned checksum sidecar.
8. **Final evidence was coupled to the end of the monolithic run.** Interruption left no execute result describing the last completed durable stage.

1. Repeat the read-only Git, process, lock, database, free-space, and candidate-file preflight.
2. Freeze a content-addressed manifest for exactly the existing 329 files, binding 337,421,353 bytes and 3,738,096 rows to their source releases, schemas, hashes, timestamps, partition identities, and original generation revision.
3. Add a versioned checksum cache keyed by path, size, and modification time so unchanged validated files do not require repeated hashing.
4. Use a dedicated `finalize-fd1-from-existing-parquet` command that refuses provider access, source scanning, Parquet generation, and unmanifested files.
5. Convert identity mappings into a compact staging input and load them into a run-scoped PostgreSQL staging table with `COPY`.
6. Reconcile mappings with set-based SQL. Record inserted, exact-reuse, unresolved, and conflict counts; fail closed on a conflicting semantic key.
7. Persist bounded stage checkpoints for files validated, identities staged, identities reconciled, partitions staged, warehouse validated, and finalized.
8. Keep staged state invisible to normal reads and use one short atomic transaction for final visibility promotion.
9. Emit console, durable-log, and checkpoint heartbeats every 30 seconds, with throughput and an honest ETA or `ETA unavailable`.
10. Rehearse COPY, conflict handling, rollback, checkpointing, promotion, and resume on a representative sample, not by repeating a full rollback load.
11. Execute the full recovery once, then prove a second provider-free invocation is idempotent.
